# 研究操作流程

`/onboarding`按当前已经持久化的配置、原件、准入数据、项目、Notebook、批次、任务和运行结果，给出下一步入口。页面只读取状态，不派发任务，也不靠刷新页面推进队列。关闭浏览器后，已经提交到`JobManager`的任务和`BatchSupervisor`管理的批次继续在服务进程内运行；服务重启时，旧实例未完成的任务会标为中断，不会伪称自动续跑。

## 从原件到固定数据版本

1. 在`/intake`上传CSV、TSV或Parquet原件。网页上传上限为24MiB，服务端保存原始字节、文件名、大小和SHA-256；后续步骤不会覆盖原件。
2. Studio调用独立quant-data-kit环境解析样例。解析失败页显示后端实际错误，并允许在同一原件上修改UTF-8、UTF-8 BOM、GB18030编码或逗号、制表符、分号、竖线分隔符后重试。样例最多用于确认字段，不代表全量质量通过。
3. 用户明确填写规范列名、类型、日期格式、单位、唯一键、来源、供应商、时区、复权和历史可得性，再提交导入。网页最多映射200列；更宽或更大的数据应使用QDK命令行。
4. `JobManager.submit(action="intake")`原子地把`prepared`请求绑定到任务并改为`queued`。HTTP层不重复写`queued`或`job_id`。取消、执行失败和服务重启后的中断状态由任务管理器同步回导入记录。
5. 质量页按后端真实回执展示实际检查范围、是否全量扫描、问题严重度、问题行、问题列、影响数量和修复建议。后端失败且`data`为空时仍显示错误回执，不把失败当作通过，也不返回空白成功页。
6. 只有指定用途和范围的准入检查返回`allowed=true`时，才能把该固定版本登记到Studio数据目录并连接研究项目。

失败的解析、映射、质量检查和任务尝试都会保留。重试需要创建新的请求；系统不会静默改写失败记录、自动补值或猜测单位。

## 刷新已有数据

上传新原件后，可在字段映射页选择一个已经发布的旧导入请求。Studio会读取并核验旧请求、旧契约和旧原件的字段预览，然后带入：

- 原数据集名称；
- 旧发布版本ID作为`parent`；
- 旧数据类型、字段映射、类型、日期格式、单位、唯一键和来源元数据。

自动复用要求新旧原始字段名称和顺序完全一致。出现新增列、删除列或仅顺序变化时，页面会显示差异并停止自动复用；名称和父版本仍会展示，用户须逐列重新确认映射。提交阶段会再次检查字段身份，不能通过构造表单绕过这一阻断。

## 项目、Notebook、批次和结果

通过准入的数据可连接到版本化研究项目。项目保存研究问题、固定数据版本和精确方案版本。项目页提供数据质量探索、价格收益与观测缺口、历史财务可得性三类Notebook起点；Notebook草稿只提供结构和已登记输入，不复制真实策略。提交Notebook实验时会冻结代码、项目版本、输入文件和环境记录。

批量实验先预览明确的参数网格和候选数量，用户显式提交后才进入FIFO队列。每个候选先预检再执行；成功、失败、取消和显式重试的attempt都保留。资源预算是轮询式软限额，不是操作系统级隔离。结果页应结合输入身份、日志、产物和失败原因判断；不得把合成样例称为盈利或真实市场有效性证据。

## 页面与安全边界

- 所有来自文件名、字段名、后端回执、项目名和记录的文本在进入HTML前转义。
- 所有修改状态的POST继续使用Studio现有CSRF、Origin、Host和请求大小校验。编码、分隔符和旧请求选择使用GET，只改变预览，不修改持久化任务状态。
- 原件保存在服务端接入目录；当前页面提供重新解析入口，不新增未鉴权的原始文件下载路由。
- 新手页读取`studio-settings.json`及各存储的真实记录。损坏的可选记录会被忽略或显示配置错误，不会虚构“已完成”状态。
- Studio不安装运行环境、不读取任务的私密命令行或环境变量，也不替代quant-data-kit的转换和质量规则。

## 本地验证

数据接入要求quant-data-kit源码包含`research_intake.py`，并在“首次配置”中选定该仓库的独立Python。
如果源码与常规工作区不在同一路径，可通过启动环境变量`QUANT_STUDIO_INTAKE_CONFIG`指定JSON文件：

```json
{"python":"C:/Quant/qdk-env/Scripts/python.exe","source":"C:/Quant/quant-data-kit"}
```

这里的`source`是源码仓库根目录，所有路径必须为绝对路径。此配置只连接现有环境，不安装或更新包。
Notebook环境继续按[研究工作区指南](../RESEARCH_WORKSPACE.md)独立配置；
问题导向模板通过冻结的读取器调用QDK，无需把QDK安装进Notebook环境。

可选的真实集成测试使用`QUANT_TEST_INTAKE_PYTHON`、`QUANT_TEST_INTAKE_SOURCE`、
`QUANT_TEST_NOTEBOOK_PYTHON`和`QUANT_TEST_BATCH_PYTHON`、`QUANT_TEST_BATCH_SOURCE`。
批次集成仅执行quant-crypto-basis自带的离线样例。
浏览器验收脚本为`integration/research_operations_browser.cjs`，另设`QUANT_TEST_STUDIO_PYTHON`
与绝对输出目录`QUANT_BROWSER_ARTIFACTS`，使用已有Playwright运行`node integration/research_operations_browser.cjs`。
脚本创建独立运行目录和临时本机服务，结束时关闭服务，不连接现有工作台；截图与CSV保存在指定输出目录。

维护环境的editable安装可能指向其他检出，验证时必须把`PYTHONPATH`指向当前工作树的`src`。相关测试覆盖HTTP CSRF与XSS、解析失败重试、质量失败空数据、问题位置、旧映射复用、schema变化、任务原子绑定和新手页状态读取。
